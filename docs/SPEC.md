# nullshell v0.1 架构与迁移规范

状态：架构方向和 Rust 选型已确认；具体后端协议在实现前定案。本文描述目标，不代表能力已完成。

## 已确认的项目边界

nullshell 为上游 Quickshell 提供辅助能力，不替代其运行时、原生服务、配置发现
或进程管理。QML 是使用 Quickshell 的界面配置；helper 是独立可调用的补充工具。
已有原生能力直接使用，不为统一接口而再包装一层 helper。

安装软件、管理用户配置、启动会话是三个独立动作。默认安装不部署用户 QML，
不改配置、不迁移旧状态、不启动会话。启动器只是可选便捷入口；直接运行
Quickshell 不应缺少隐藏的初始化。旧状态迁移必须显式执行。

使用者可以自行选择 Home Manager 管理配置，项目不禁止，也不主动启用。
是否由安装工具管理用户配置，由使用者决定，不是项目的安装约束。

这些是实现约束，不代表历史代码已全部通过验收。

## 产品范围

无常驻 bar；command panel 默认展示有用状态，输入后统一搜索应用、窗口与操作。
迁移保留通知、OSD、壁纸、多显示器、锁屏、greeter、Polkit 与设备控制。
第一版只承诺 Hyprland/Linux；其他 compositor 通过适配层扩展，不宣称开箱支持。

## 面板的信息层级与扩展边界

桌面空闲时保持无 bar。打开面板后，概览回答“现在是什么状态”，保留常用控制；
同一领域的对象、参数和解释放进已有详情。通知和 OSD 表达事件与短期反馈。
参考其他桌面时，先确定一项能力在 nullshell 已有交互中的位置。上游有一个
widget，并不构成本项目增加首页入口的理由。

| 层级 | 职责 | 在本项目中的例子 |
| --- | --- | --- |
| 全局搜索 | 查找应用、已打开窗口、可导航页面和可直接执行的动作。共用匹配、选择、可用性和分发逻辑。 | “电源与会话”打开页面；“截取区域”发起一次请求。 |
| 领域详情 | 展示该领域的实时对象，允许在当前列表内筛选、选择目标或填写参数。筛选文本属于页面的临时状态。 | 桌面页查看当前快捷键；电源与会话页设置保持唤醒的时长。 |
| 服务与适配器 | 服务拥有请求与策略的生命周期。适配器从权威来源取得数据，将其转换为页面可读的值。 | Hyprland 拥有绑定；桌面 idle 服务拥有保持唤醒的有效状态和截止时间。 |
| 使用者配置 | 拥有实际按键、命令绑定和个人默认值。面板、IPC 等入口复用同一项能力。 | 使用者可将截图请求绑定到自己选择的按键。 |

### 内置应用与窗口

面板是应用入口，也是内置应用的一种显示方式。Wi-Fi、蓝牙、音频、媒体播放器、通知、
外观和壁纸已有可分离页面。用户可以在面板内完成一次操作，也可以把当前页
分离至普通窗口，边做其他事边继续使用。分离时移动同一页面实例，保留选择、
输入草稿和当前操作。再次打开同一应用应聚焦已有窗口；关闭窗口后再次打开，
回到面板内。当前内置窗口与桌面 QML 同进程，生命周期有别于启动的外部应用。

音频应用的 Mixer 按 PipeWire 播放流调节音量和静音，同一应用的多个流可以独立控制。
概览显示当前 MPRIS 播放器的摘要，打开媒体应用后可选择播放器。分离窗口保留
选择，服务离线后回到可用播放器。进度、定位、随机播放和循环模式以所选播放器报告的能力为准。随机和循环只在媒体应用内操作，状态由播放器持有。
通知历史的筛选词属于页面实例，匹配应用名称和通知内容。筛选期间可逐条删除，
清除筛选后才能清空整份历史。

概览、全局搜索和电源确认留在面板内。评估新功能时，应先问用户在什么场景
需要持续打开一个窗口。已有应用可以承载的工作流优先扩展该应用；一次性动作
通过命令进入。服务订阅以实际打开的页面为准，分离窗口仍在使用的服务不能
因面板收起而停止。

### 全局入口与局部操作

判断功能是否该进入全局搜索，要看用户选中一行后会发生什么。可以执行的任务
或可以打开的页面适合用已有 action 表达。用于阅读的领域记录留在所属页面；
一个动作的参数也不按可能取值展开成一组命令。新增领域能力不应要求通用
搜索识别某个 compositor 的协议字段、运行外部工具或专门绘制该领域的数据行。

以下三例说明同一原则在不同能力上的落点：

- **快捷键速查**：展示当前 Hyprland 实例报告的绑定。适配器负责查询和解释
  修饰键掩码；页面负责显示和筛选。缺少描述时显示可确认的 dispatcher；
  查询失败或没有绑定时展示对应状态。示例按键只属于隔离预览和测试。
  在全局搜索中增加 `keys:` 语法、执行 `hyprctl` 并创建专用结果类型，会把
  一个只读目录的实现扩散到搜索层。
- **保持唤醒**：快捷开关表达启停，时长是同一 idle 能力的参数。限时请求
  的截止时间、到期恢复和长期选择由同一状态所有者处理；关闭面板或重启
  桌面不改变用户意图。将“一小时”和“结束计时”登记为两个顶层命令，会让
  一项能力的局部选项占用全局命令目录。
- **区域截图**：选区是用户当场提供的参数，完成后有独立结果。面板可通过
  现有动作分发发起截图，IPC 也可发起同一请求；截图组件协调隐藏面板、
  选区取消和失败反馈。选区图像通过管道交给 Satty；标注、复制、保存和另存为
  都属于编辑器，只有用户选择保存时才写入截图文件。按键分配属于使用者。

对应到代码，`ShellActions.qml` 声明可发现的入口并分发请求，
`DesktopSearch.qml` 对全局候选项做匹配，`LauncherPanel.qml` 管理打开、关闭和
导航。领域服务提供状态和操作结果。按钮、搜索和 IPC 指向同一个操作所有者，
各入口不各自保存一份状态。同一能力可以只在详情中提供，并不需要占据每一层。

验收时用三个变化检验边界。更换一组 compositor 绑定，再次打开速查页应反映新数据。
改变一次唤醒时长，命令目录应保持稳定。关闭发起操作的页面，已受理的请求和
有效策略应继续由各自的所有者处理。

## 分层与所有权

1. QML views：布局、交互、动画、短期页面状态；不得构造系统命令或实现认证协议。
2. Application：搜索 provider、稳定身份、action 分发、请求生命周期；不依赖页面生命周期。
3. Adapters：按功能提供能力、可用性、状态、异步结果；不要为每个原生属性重复建立模型。
4. Providers：Quickshell 原生 API 优先；缺失协议用自有 helper；CLI 过渡实现明确登记。
5. Configuration/state：配置默认值、用户偏好、运行状态分别有版本与验证。
6. Integration：打包、会话生命周期、PAM/greetd/systemd/portal 接入；不包含个人 UI 偏好。

设备状态以原生系统服务为准。操作 accepted 不等于 completed；适配层必须区分
请求受理、结果和超时，并处理取消、设备消失、服务重连。UI 不解析 helper 输出。

## 进程与安全边界

- desktop：panel、通知服务、OSD、壁纸及桌面适配层；详情页按需加载。
- lock：独立用户进程，使用 Wayland session-lock 与 PAM；禁止认证期间热重载。
- polkit：独立用户认证代理；授权决策由系统 Polkit authority 执行。
- greeter：greetd 启动的专用账户进程，共享 UI 资源，不加载用户 HOME；可读取安装时授权的独立外观快照。
- 自有 helper：仅在明确需要的能力上启用；默认不增加通用常驻 daemon。

独立打包不会替代 compositor、PipeWire、NetworkManager、BlueZ、logind、PAM、
Polkit 或 portal。nullshell 的目标是统一交互与协调，不重写这些基础服务。
桌面、locker 和 Polkit 由 Hyprland 显式直接启动，不安装 Quickshell 保活 unit。
Quickshell 使用 --no-duplicate 防重复启动；退出会话时客户端随 Wayland 断开退出。
蓝牙 helper 按需运行；仅外观 Settings portal 是已定义的专用 D-Bus 激活进程；不增加通用后台宿主。

## 配置与动态数据

wallpaper.json 保留静态默认配置；终端 argv 与 idle 超时有独立用户配置。
Keep awake、通知历史、壁纸选择，以及 greeter 上次成功登录的用户名和会话
分别保存状态；greeter 状态由专用账户持有。

目标路径：

- 包内 defaults：只读、可移植默认值，不含个人用户名、HOME 或显示器名称。
- $XDG_CONFIG_HOME/nullshell/config.json：版本化用户设置，用户/dotfiles 管理。
- $XDG_CONFIG_HOME/nullshell/hyprland-displays.lua 及配套记录：明确启用后由 Hyprland 读取的确认布局，不是安装器部署的文件。
- $XDG_STATE_HOME/nullshell/：Keep awake、通知历史及 UI 保存的偏好覆盖；原子写入。
- $XDG_CACHE_HOME/nullshell/：可重建缓存；$XDG_RUNTIME_DIR 下放临时 IPC 资源。
- greeter：独立系统状态保存上次成功认证的用户名与会话 ID；不读取上述用户路径。

优先级：包默认值 < 用户配置 < 明确允许 UI 修改的持久覆盖。
每个状态域只有一个写入者，多进程读者订阅更新。
每个可修改字段须声明所有者、覆盖/重置行为和是否即时生效，不允许整份运行状态覆盖配置。
空闲计时页只覆盖调暗、锁屏与息屏的时间，保存到 `idle-policy.json`；恢复默认后跟随用户配置。Keep awake 单独持久化，合盖、电源键和系统挂起策略不归该页。
无效热加载保留上一次有效配置并反馈错误；首次启动使用安全默认值。
布局、动画和主题定义直接在本地 QML 配置仓库编辑。
外观同步例外：桌面将当前深浅模式及实际颜色导出为 version 1 数据快照；
greeter 只读取验证过的导出数据，不加载用户提供的 QML；锁屏和 Polkit 保持用户侧机制。
跨账户导出由安装配置指定来源账户与目录；不增加常驻 daemon。
外观和壁纸是独立事件域。greeter 壁纸只同步全局默认，复制受限图片而非 HOME 链接；
独立描述文件原子发布，资源只保留两个固定槽位，取消时清理，不积累历史。
深浅色由桌面持久保存，默认手动；可配置本地日出日落调度，固定坐标无需联网，
自动外观默认从本机时区离线估算位置，也支持固定坐标和显式启用的 BeaconDB IP 定位。快捷命令的手动覆盖有到期时间并独立持久化。外观页可选择浅色、深色、自动及定位来源；
界面偏好单独保存于 appearance-policy.json，只覆盖声明的外观字段，可恢复配置默认值。
通过自有 Settings portal 后端只读发布
有效模式，独立 D-Bus 激活，不承担主题决策。greeter 未登录时使用最后一次快照。
具体契约与发行版分层见 docs/APPEARANCE.md。
运行态和已有行为设置继续使用现有 XDG 文件；helper 与 QML 仅要求协议兼容。
桌面入口为仓库根目录 shell.qml，runtime 包不绑定 QML 快照。
greeter 默认使用包内 QML；可通过显式安装命令复制工作树资源到系统管理目录覆盖。
安装仅处理代码文件，不执行用户 QML、不重启认证进程；下一次 greeter 启动生效。
主题数据同步、QML 程序安装与运行依赖更新是三个独立接口。
显示器页面使用 helper 查询和校验布局；试用只改运行规则，确认后才由 Hyprland 原子写入对应屏幕组合的记录。没有适用记录时使用 Hyprland 原生规则；布局恢复不需要桌面进程。详见 [显示器配置](DISPLAYS.md)。
旧 quickshell 状态按版本迁移一次，保留源文件；尤其保证 Keep awake 不因迁移丢失。

## 扩展后端契约

Rust 部分承担独立的系统集成能力，以 Cargo 构建，使用 serde、zbus 和 Tokio。
“系统集成”描述职责，对外保留已经发布的可执行名 `nullshell-helper` 和子命令。
这个名字已被独立更新的用户 QML、D-Bus 激活文件和发行包使用。内部重组无需
迁移这些调用方。今后若某项能力需要独立安装、权限或升级周期，应按具体协议
为该程序命名，并说明旧入口如何过渡。

后端命令直接接受自身协议的输入，可以在没有 Quickshell 实例和用户 QML 的
环境中单独测试。配对使用 BlueZ 设备和 Agent1 回调，自动外观定位不使用 D-Bus，
睡眠握手使用 logind 会话和 inhibitor FD。sleep-bridge 默认通过
`nullshell lock` 等待锁定确认，也支持注入遵守相同退出契约的 argv。
这个集成点属于命令边界；后端不查找 locker 的 QML 对象，也不自行认证。
原生设备对象、用户选择与面板导航继续分别由 Quickshell 和桌面应用层持有。

代码按具体能力组织。CLI 入口负责子命令分发、帮助和退出状态，协议模块管理
该协议的订阅、请求、取消和资源释放。一个可执行文件可启动不同寿命的进程：
导出及查询完成即退出，配对 agent 随一次配对退出，sleep-bridge 随登录会话
结束，Settings portal 由 D-Bus 激活。它们不通过共享的后台宿主管理。
新增 Rust 能力时记录原生 API 的具体缺口、权威数据源、调用协议和退出条件。
用户界面通过适配层消费结果；后端的构建和协议测试独立于 QML。

按需子进程可使用带版本的 JSON Lines/stdin/stdout：请求 ID、结果、事件、取消、
超时、消息长度限制和退出行为必须定义；日志走 stderr，敏感信息禁止进日志或 argv。
需要共享常驻能力时另行设计 Unix socket 或 D-Bus，不提前搭建插件宿主。
睡眠延迟抑制器必须由持有实际文件描述符的进程维护；普通 JSON 应答不能替代锁定确认。

## 能力迁移顺序

1. 提取现有代码与许可证/来源记录，建立独立可构建包及安全预览；不先重写 UI。
2. 解耦个人 Hyprland Lua、用户名、终端、壁纸；提供稳定 CLI 和配置 schema。
3. 切换 dotfiles/Nix 引用；验证成功后删除旧实现，避免两个长期维护源。
4. 优先替换 Bluetooth 配对的文本交互桥，使用实际 BlueZ Agent1 协议。
5. Rust sleep-bridge 接替 hypridle 的 logind 睡眠握手，不接管 Quickshell 空闲计时。
   必须取得锁屏协议确认后才提前释放 delay inhibitor；失败时仍受 logind 最大延迟限制。
   隔离测试覆盖超时、文件描述符释放、会话与服务消失；真实 suspend/resume 需单独验收。
6. 根据原生 API 的实际缺口增加后端，不重写已经可用的音频、媒体、电池等模块。

## 打包和开发目标

独立 flake 默认只安装 runtime（上游 Quickshell、helper 与依赖），另提供 greeter、预览入口、开发环境与 NixOS 环境集成模块。
当前没有专用 HM 配置模块；默认安装不管理用户 QML，不包装全局 Quickshell。
使用者可显式选择配置管理工具，用户会话仍使用原生配置发现。
普通发行版提供同一份资源与命令的安装方式；不要求安装 Nix。
用户 QML 独立维护；只有系统 greeter 使用只读资源快照，开发预览显式选择源码目录。
预览不注册通知/Polkit 服务，不认证、不锁屏、不执行电源操作。
后端按最终语言使用标准工具链；QML 使用 Qt 工具检查，Nix 使用 nixfmt。

## 参考 DMS 的规则

参考其模块边界、原生能力使用、协议实现和生命周期处理；不搬入整套产品 UX。
引入代码前记录具体仓库、commit、文件、许可证及修改；保留所需声明。
尚未审计 DMS 当前代码或许可证，不假定其组件采用统一许可。

## 验收

- 保留目前搜索、窗口操作、通知、壁纸、锁屏和设备操作行为；动态标题不重建 hover 项。
- Keep awake 跨重载/重启保持；多屏热插拔正确；配置错误不会破坏有效状态。
- desktop 重启不影响已启动应用、锁屏或正在进行的 Polkit 会话。
- 不同 DE 不误启动桌面服务；缺失硬件/可选服务给出明确不可用状态。
- greeter 不依赖用户目录；实际 PAM/greetd/睡眠流程需要真实会话验收，预览不算通过。
- 仓库只含源码、正式文档及有意义的测试；构建产物、截图、临时诊断留在仓库外。

## 材质与回退

Quickshell 是上游运行时，nullshell 维护 QML、桌面适配和必要的 helper，
不维护 Quickshell 分支。材质参数属于内部 UI 实现，本轮不新增用户配置选项。

桌面玻璃使用 BackgroundEffect 的区域请求，不依赖个人 layer rules 开启模糊。
当前 Quickshell 接口没有通用的能力或请求成功回执；因此只对已支持的 Hyprland
读取 `decoration:blur:enabled`，启动及浮层重新打开时刷新。未知合成器、禁用、
查询失败和超时均使用不透明底色，并取消模糊请求。用户针对单个窗口的规则
仍可能覆盖合成效果；这不是逐窗口模糊成功的保证，也不是跨合成器支持声明。
锁屏自行绘制并模糊壁纸，使用独立的 frosted 材质，不读取桌面截图。

## 外观同步的所有权边界

| 内容 | 所有者/写入方 | 消费者 |
| --- | --- | --- |
| 用户会话当前深浅模式 | 桌面手动/自动策略 | 保存现有用户侧模式状态，通过 Settings portal 发布应用偏好 |
| 配色与界面程序 | nullshell 用户侧 QML/公共视觉组件 | 各界面使用组件；只导出颜色数据给 greeter |
| 用户壁纸选择及原图 | 用户侧 WallpaperState/用户文件 | 桌面与锁屏沿用现有用户侧机制 |
| greeter 颜色快照、壁纸描述及图片副本 | 用户侧按需导出器 | greeter 只读，预览可注入相同数据 |
| 跨账户路径和目录权限 | 系统安装模块 | 向生产者和消费者注入，不由 QML 猜测 HOME |
| 登录过程及上次登录选择 | greeter 专用账户 | 与外观目录独立，不向用户侧导出 |

共享 QML 组件不等于共享可写运行状态。greeter 外观快照是用户侧结果的派生副本，
不是第二套主题配置，不允许反向覆盖用户设置。外观和壁纸分别由自己的事件触发；
一个域更新失败，不重置另一个域或认证过程。greeter 没有跨账户写入用户偏好的接口。
本次不改变锁屏/Polkit 的入口或状态协议，也不增加全局外观 daemon。
